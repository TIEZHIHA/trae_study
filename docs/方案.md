# 基于数据挖掘的医药知识图谱问答系统 · 方案（A）

> 对应第 6 章《基于数据挖掘的医药问答系统》。主线：数据挖掘 → 知识图谱 → 智能问答。
> 方案类型：A（本地知识图谱 + 规则/模型混合问答，不依赖在线大模型）。

## 一、做法

### 1.1 总体架构

```
┌──────────────── 离线知识生产 ────────────────┐
  data/inbox/*.md  ─┐
  网页采集 crawler  ─┼→ clean（清洗/解析）→ build_graph（三元组）→ storage（图谱）
  审核队列 pending  ─┘                                     └→ question_bank（题库）
                                                              └→ resource（四类资产）
┌──────────────── 在线问答服务 ────────────────┐
  /ask → preprocess → NER（规则+BiLSTM）→ 意图（规则+TextCNN）
       → 关系路由 → 参数化查询 → 模板答案 + 安全提示
┌──────────────── 后台常驻 ────────────────────┐
  watchdog 目录监听 → 同步；定时同步；定时备份（DRY_RUN 默认开）
```

### 1.2 五站数据形态

| 站 | 形态 | 落点 |
| --- | --- | --- |
| 1 | 原始 HTML / Markdown | `raw_kb`（只插不改） |
| 2 | 清洗记录 record | `clean_kb` |
| 3 | 三元组 | `edges` + `nodes` |
| 4 | 图谱查询结果 facts | `query_facts()` |
| 5 | 答案文本 + 证据路径 | `/ask` 响应 |

### 1.3 关键设计

- **实体识别**：双向最大匹配 + 启发式择优（词数少 → 单字少 → 专词完整）；训练好的 BiLSTM 作为补充，规则未命中时接管。
- **意图分类**：9 类问句，第一版实现 4 类（用药/症状/检查/预防），其余 5 类明确返回「待扩展 + 扩展路径」。
- **查询**：全部参数化（`?` 占位符），响应里同时给出等价 Cypher，便于对照方案原文。
- **四级兜底**：空结果不编造 / 低置信度澄清 / 高风险建议就医 / 待扩展说明。高风险判定优先于澄清，医学场景先劝就医。
- **幂等**：`doc_id = sha256(相对路径 + 内容)`；节点 `(label,name)` 唯一、边四元组唯一，重跑不翻倍。
- **安全提示**：每条答案必带「仅供健康科普参考」声明。

### 1.4 与方案原文的偏离

| 原文 | 实现 | 原因 |
| --- | --- | --- |
| MongoDB + Neo4j + Docker 四服务 | SQLite 单文件 + 两服务 | 验收机未装 Docker；表名/字段/方向/唯一约束保持对齐 |
| 参数化 Cypher | 参数化 SQL，附等价 Cypher | 存储层替换，查询语义一致 |
| 神经网络模型为唯一通道 | 规则优先、模型补位 | 模板生成的训练集规模有限，混合路由更稳，且模型缺失可降级 |

## 三、实施步骤

1. **建库**：`storage.init_db()` 建 7 张表与唯一约束。
2. **采集**：`crawler.fetch_html` 抓取（UA/超时/重试/编码），`parse_html` 抽六字段，落 `data/inbox/crawled`。
3. **清洗**：`clean.parse_document` 统一 Markdown / JSON，`normalize_list` 去空去重，保留否定词、剂量、时间。
4. **分词**：`segment.build_dict` 合并实体词典与基础词表；`segment.segment` 双向最大匹配。
5. **建图**：`build_graph.extract_triples` 抽三元组，`merge_record` 按 Label+name MERGE，方向统一 `Disease → 目标`。
6. **题库**：`kb.question_bank.generate_for_record` 自动生成问句 + 标准答案，作为回归集。
7. **资产**：`resources.export_all` 导出词典、实体表、关系候选表、训练集。
8. **训练**：`models.train` 训练 BiLSTM + TextCNN，仅指标创新高保存 `best_model.pt`，输出 `metrics.jsonl` 与曲线。
9. **问答**：`qa_service.ask` 六步链路，返回 `trace` / `query` / `evidence` / `timings`。
10. **后台**：`runtime.start` 启目录监听、定时同步、定时备份。
11. **验证**：`verify.py` 跑 V1–V8 + VA1–VA12 + S1–S4；`selfcheck.py` 出模拟评分。

## 四、演示设计

### 4.1 演示页六区块

状态灯（`/health`）→ 答案与 `status` → 证据路径（`(:Disease)-[:REL]->(:Label)` + 来源文件）→ 分段耗时（预处理/模型/NER/意图/查询/总计）→ 知识库统计（节点/关系/题库/文档）→ 备份状态。

### 4.2 必演用例

| 用例 | 问句 | 预期 |
| --- | --- | --- |
| 正常·用药 | 风热感冒吃什么药 | ok，命中 4 种药 |
| 正常·症状 | 风热感冒有哪些症状 | ok |
| 正常·检查 | 高血压需要做什么检查 | ok |
| 正常·预防 | 怎么预防2型糖尿病 | ok |
| 空结果 | 急性胃炎需要做什么检查 | empty，明确说无记录 |
| 低置信度 | 那个东西能不能吃 | clarify，请补充疾病名 |
| 高风险 | 孕妇胸闷气短怎么办 | safety，建议就医 |
| 待扩展 | 风热感冒和板蓝根一起吃会冲突吗 | pending，给扩展路径 |

### 4.3 演示顺序（10 步）

1. 启动 `up.ps1` → 2. 打开网页看状态灯 → 3. 点「正常·用药」→ 4. 看证据路径 → 5. 点「空结果」→ 6. 点「高风险」→ 7. 点「待扩展」→ 8. 丢一个新 `.md` 进 inbox，看节点/题库增加 → 9. 点「立即备份」看扫描报告 → 10. 切 `/mobile` 演示移动端。

### 4.4 追问准备

- 为什么用 MERGE 不用 CREATE：保证四元组唯一，重复同步不翻倍。
- 为什么规则优先：词典命中是确定性的；模型由模板数据训练，规模有限，作为长尾补充更稳。
- 为什么安全分支提前：医学场景下「先劝就医」优先于「先追问」。
- 为什么用 SQLite：验收机无 Docker；链路与判据不变，迁移只改存储层。

## 五、迭代与上下文（第二版设计）

### 5.1 权威数据源

- 语料只接受三类来源：公开药品说明书、国家/省级卫健委科普页、教材条目；页面需可溯源（`source` 字段保留原始 URL 或文件路径）。
- 拒绝论坛问答、营销软文、无出处的“偏方”，审核开关 `KB_REQUIRE_REVIEW=true` 时先进 pending 队列人工确认。

### 5.2 指标绑定评测集

- NER 的 **94%** 与意图的 **90%** 是绑定固定评测集的口径：评测集由题库自动生成（`data/train`），每次训练先固定随机种子 2026，dev 集占 15%，指标记录在 `metrics.jsonl`，可复算。
- 题库回归通过率基线 **95%**，低于基线即视为回归失败。

### 5.3 会话标识、历史记忆与上下文检索

- **会话标识**：`/ask` 增加 `session_id`，同一会话的问答写入 `qa_logs.session_id`。
- **历史记忆**：保留最近 3 轮「实体 + 意图」，用于省略主语的追问（“那它需要做什么检查”）。
- **上下文检索**：把上一轮实体作为本次查询的默认实体，置信度低于阈值时再澄清。
- 第一版未启用会话，字段与调用点已预留，属于第二版迭代范围。
